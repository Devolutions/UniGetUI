# Third-party licenses

Generates `THIRD-PARTY-NOTICES.txt` and `THIRD-PARTY-NOTICES.json` from a UniGetUI build, as
required by PI-831 (UNI-33): one block per third-party component the build ships, with its own
copyright and license text. The About page and the TUI About dialog read the JSON; the text file
is what they open as "the full notices file".

The tool is a copy of `DevTools/ThirdPartyLicenses` from the private `Devolutions/RDM` repository
(commit `4020053fc3c04876275f9ce0f2880283d13a6d8b`). Its full documentation is the
`third-party-licenses` skill in that repository. The scripts under `Private/` and the template are
unchanged; `config/` holds UniGetUI's own entries only.

## Running it

Build or publish UniGetUI in Release for one runtime, then:

```powershell
./scripts/generate-third-party-notices.ps1 -PublishDir <publish folder> -RuntimeIdentifier win-x64 -OutputDir <folder>
```

The wrapper reads `UniGetUI.deps.json` from the build folder under `src/UniGetUI.Avalonia/bin`
(a NativeAOT publish folder has none), the shipped native files from `-PublishDir`, and the
version from `CoreData.VersionName`. On Windows runtimes it also merges `config/pinget-crates.json`
and `config/manual-components.windows.json`. It exits with 1 when a component has an error; the
files are written either way.

## In the release pipeline

- `build-release.yml` runs the wrapper for every runtime and ships both files next to the binaries
  (each runtime gets its own, since their native libraries differ). The step may fail on license
  errors without stopping the release; a missing file does stop it.
- After a stable release is published, `commit-third-party-notices` opens a pull request that
  copies the win-x64 files to `src/UniGetUI.Avalonia/ThirdPartyNotices/` when a component changed.
  It uses `DEVOLUTIONSBOT_TOKEN`, since GitHub runs no checks on pull requests opened with
  `GITHUB_TOKEN`; a re-run updates the same branch and pull request. Development builds ship that
  copy; never commit one generated locally.
- The wrapper deletes any notices files in the output folder before anything else, so a run that
  fails early never leaves the committed copy behind for the release to ship.

## What the config holds

| File | Purpose |
|---|---|
| `package-overrides.json` | Missing license metadata, the gsudo-based elevator, and the libraries compiled into the ANGLE, Skia and HarfBuzz native packages (`notices`) |
| `license-url-mappings.json` | License URLs mapped to SPDX ids |
| `excluded-packages.json` | Devolutions' own packages, our own native files the tool cannot recognize as ours (the macOS notification bridge `.dylib`, matched by base name), and files declared by hand instead |
| `manual-components.json` | Content no build output describes, on every platform: the Inter font, the Icons8 icons |
| `manual-components.windows.json` | The same, Windows only: the signature-check DLL, the WinGet COM metadata, and what the installer itself ships (Inno Setup, and InnoDependencyInstaller, copied in 2024 under CPOL 1.02 before its 2026 relicense to MIT). `versionFromPackageReference` takes the version from the csproj, and refuses a package referenced at several versions |
| `pinget-crates.json` | The Rust crates compiled into `pinget.exe`, generated by `Update-PingetCrates.ps1` |
| `pinget-crate-overrides.json` | Crate copyright holders the crates themselves do not name |
| `allowed-licenses.json`, `approved-packages.json` | Licenses that pass without review, and legal's approvals |

## pinget's crates

pinget does not commit its `Cargo.lock`, so `Update-PingetCrates.ps1` rebuilds it: it resolves
the `v<version>` tag of a local pinget clone against crates.io as published at the tag's time
(`cargo generate-lockfile --publish-time`, which needs a nightly toolchain), keeps the normal,
non-proc-macro dependencies of `pinget-cli` for the Windows targets, and refuses the result unless
every crate version found in the shipped `pinget.exe` (from the NuGet cache) is in it. License
texts and NOTICE files come from each crate's own package.

```powershell
./scripts/third-party-licenses/Update-PingetCrates.ps1 -PingetRepository C:\DEV\pinget -Toolchain nightly-x86_64-pc-windows-msvc
```

Run it whenever `Devolutions.Pinget.Cli.Rust` is bumped: the wrapper refuses a crate list made for
another version. Its license errors are reported by that run, not by the release run that merges it.

## Fixing a reported component

- No license, a license given only as a URL, or a `Custom` license whose text is a standard one:
  add the package to `config/package-overrides.json`, or the URL to `config/license-url-mappings.json`.
- A binary that no package lists: an entry keyed by its file name in `config/package-overrides.json`.
- Something no build output describes: declare it in a manual components file, and exclude the bare
  file in `config/excluded-packages.json` if needed.
- A license outside `config/allowed-licenses.json`: legal decides; once approved, record it in
  `config/approved-packages.json` with the hash the error prints.

## Licenses outside the allow-list

PI-831 leaves enforcing an approved-license list out of scope, so `LicenseNotAllowed` is
informational here: the component is still written with its full license text, and the release
goes on. These are the ones reported today:

- `Microsoft.Windows.SDK.NET.Ref`: Windows SDK license terms (text from the SDK's `sdk_license.rtf`).
- Inter: `OFL-1.1`. Icons8 icons: Icons8 license.
- Installer: Inno Setup license, and `CPOL-1.02` (InnoDependencyInstaller).
- pinget crates: `Unicode-3.0` (the ICU4X crates), `MPL-2.0` (option-ext), `MIT-0` (borrow-or-share),
  `CC0-1.0 OR MIT-0` (ppmd-rust), `bzip2-1.0.6` (libbz2-rs-sys).

The `NoticeNotChecked` warnings for SkiaSharp, HarfBuzzSharp and Avalonia.Controls.WebView were
checked by hand: none of their repositories has a NOTICE file at the commit the package was built from.

## Updating from RDM

Copy `Invoke-ThirdPartyLicenses.ps1`, `Private/`, `templates/` and the tests over this folder,
keep `config/` and the removal of the RDM-specific `SixLabors.ImageSharp` test in
`ThirdPartyLicenses.tests.ps1`, then run `Invoke-Pester scripts/third-party-licenses`.
